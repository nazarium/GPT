# Етап 2 — сценарій Telegram-бота Archi-Create Partners

Актуальний обсяг і нумерація етапів — у [PLAN.md](PLAN.md), редакція від 18.11.2026. Власник працює через Sheets і Drive; попередній поділ на черги та позначення MVP не застосовуються. Погоджені повідомлення й основні сценарії бота збережено.

Версія 1 від 18 листопада 2026 року. Статус: погоджено користувачем повідомленням «погоджуемо». Бот ще не створений і не запущений.

## 1. Головне меню та привітання

У головному меню рівно дві кнопки: «Подати пропозицію» та «Оновити матеріали». Дії «Пропустити», «Зберегти», «Назад» тощо з'являються лише всередині відповідного кроку діалогу. Окремої реєстрації немає. Не вимагати Google-акаунт, адресу офісу, код ЄДРПОУ, сайт чи оплату.

Оригінальний текст привітання збережено дослівно:

> **Вітаємо в партнерській системі Archi-Create!**
>
> Ми приймаємо пропозиції від виробників, дистриб'юторів, постачальників будівельних матеріалів та послуг.
>
> Ви можете надіслати інформацію про послуги, продукцію, каталоги, прайс-листи та умови співпраці.
>
> Ваші матеріали будуть збережені в нашій базі. У разі виникнення потреби ми самостійно зв'яжемося з вами.
>
> Реєстрація не гарантує замовлень чи особистої зустрічі.

Окреме пояснення після привітання:

> Для подання достатньо назви компанії, контакту та пропозиції — тексту, файлу або посилання. Категорії, бренди, регіони та умови можна додати за бажанням. Ви зможете самостійно оновлювати матеріали через цей бот.

## 2. «Подати пропозицію» — перше подання

### Крок 1. Компанія

> Як називається ваша компанія або бренд, який ви представляєте?

Обов'язкове текстове поле company_name. Тут бренд може бути назвою представленого бізнесу; окремий список brands необов'язковий. Порожнє повідомлення, пробіли або файл замість назви не приймати:

> Напишіть назву компанії текстом.

### Крок 2. Контакт

> Як із вами зв'язатися? Напишіть телефон, email або інший зручний контакт.

Обов'язкове поле contact: текст або надісланий контакт Telegram. Не вимагати телефон та email одночасно або доступ до адресної книги. Не підставляти username замість явно наданого контакту.

Якщо придатного контакту немає:

> Додайте, будь ласка, контакт для зв'язку — наприклад, телефон або email.

### Крок 3. Пропозиція

> Надішліть вашу пропозицію текстом, файлом або посиланням. Можна надіслати кілька повідомлень. Коли завершите, натисніть «Готово».

Приймається будь-який один варіант або їх поєднання: непорожній текст, прийнятий файл, http/https-посилання. Підписи до файлів зберігати разом із текстом пропозиції. Посилання реєструвати як матеріали kind=link без обов'язкового завантаження зовнішньої сторінки. Не обіцяти пошук усередині PDF у MVP.

Після фактичного прийняття файлу в чернетку:

> Додано: {назва файлу}. Можете надіслати ще матеріали або натиснути «Готово».

«Готово» без жодного прийнятого матеріалу чи тексту:

> Спочатку надішліть текст пропозиції, файл або посилання.

Помилка приймання файлу:

> Не вдалося прийняти файл «{назва файлу}». Спробуйте ще раз або надішліть посилання на нього.

Точні ліміти та допустимі типи файлів перевірити на етапі 3; неперевірених чисел у повідомленнях не вказувати. Невдале вкладення не виконує вимогу до пропозиції. Якщо прийнято лише частину файлів, показати невдалі та запропонувати повторити або явно продовжити без них.

Для голосового чи іншого непідтримуваного повідомлення:

> Надішліть, будь ласка, пропозицію текстом, документом або посиланням.

### Крок 4. Перевірка та необов'язкові відомості

> Перевірте пропозицію:
>
> Компанія: {назва}
> Контакт: {контакт}
> Пропозиція: {текст або «Матеріали без текстового опису»}
> Прийнято файлів: {кількість}
> Посилань: {кількість}
>
> Можна зберегти зараз або додати необов'язкові відомості.

Контекстні дії: «Зберегти», «Додати відомості», «Виправити», «Скасувати».

«Додати відомості»: вибір «Категорії», «Бренди», «Регіони», «Умови», «Готово». Для кожного поля — довільний текст або «Пропустити». Не вимагати вибору із закритого довідника.

| Поле | Повідомлення |
| --- | --- |
| Категорії | Які категорії продукції ви пропонуєте? Можна пропустити. |
| Бренди | Які бренди ви представляєте? Можна пропустити. |
| Регіони | У яких регіонах ви працюєте або здійснюєте доставку? Можна пропустити. |
| Умови | За бажанням опишіть умови співпраці. Можна пропустити. |

Після «Готово» повернутися до перегляду з доданими відомостями. «Виправити» дозволяє змінити назву, контакт або матеріали без повторного введення інших даних.

### Крок 5. Успішне збереження

Лише після збереження записів і всіх прийнятих файлів:

> Дякуємо! Вашу пропозицію збережено.
>
> Якщо виникне потреба, ми самостійно зв'яжемося з вами. Реєстрація не гарантує замовлень чи особистої зустрічі.
>
> Щоб змінити контакти або матеріали, натисніть «Оновити матеріали».

Повернути дві головні кнопки. Власнику не надсилати Telegram-повідомлення, листи або інші сповіщення про подання чи оновлення.

## 3. Повторне подання

Якщо Telegram-користувач уже має компанію, показати її назву; якщо кілька — запропонувати вибір лише власних компаній.

> Для компанії «{назва}» вже є запис. Можете подати нову пропозицію або оновити наявні матеріали.

Контекстні дії: «Нова пропозиція», «Оновити наявну», «Інша компанія», «Назад».

- «Нова пропозиція»: використати збережені назву й контакт, почати з матеріалів. Перед збереженням дані можна виправити.
- «Оновити наявну»: перейти до оновлення.
- «Інша компанія»: почати нову анкету того самого користувача. Не об'єднувати компанії лише за однаковою назвою.

Запропоноване правило MVP: один користувач може представляти кілька компаній; у кожної компанії один прив'язаний Telegram-користувач. Передачу запису іншому представнику й кількох представників однієї компанії визначити на етапі 4. Знання назви чи контакту не дає права редагувати запис.

## 4. «Оновити матеріали»

Якщо записів немає:

> Для вашого Telegram-акаунта поки немає збережених пропозицій. Натисніть «Подати пропозицію», щоб додати першу.

Не дозволяти знаходити й прив'язувати чужий запис за телефоном, назвою, email або пересланим посиланням.

Якщо записи є, показати лише власні компанії. Після вибору:

> Що бажаєте оновити для «{назва компанії}»?

Контекстні дії: «Контакти й назва», «Пропозиції та файли», «Додаткові відомості», «Назад».

**Контакти й назва:** вибрати поле, ввести значення, переглянути, натиснути «Зберегти зміни». Інші поля залишити. Обов'язкові назву й контакт не можна очистити.

**Додаткові відомості:** змінити необов'язкове поле або вибрати «Очистити поле». «Пропустити» під час редагування означає залишити попереднє значення, а не очистити.

**Пропозиції та файли:** вибрати власну пропозицію за коротким описом або назвою першого матеріалу та датою оновлення. Якщо пропозицій немає, запропонувати додати нову. Далі доступні «Змінити текст», «Додати матеріали», «Замінити матеріал», «Прибрати матеріал», «Назад».

- Додавання не замінює попередніх файлів.
- Для заміни спочатку вибрати конкретний файл або посилання, прийняти новий матеріал, потім підтвердити заміну. До успішного збереження старий залишається актуальним.
- Перед прибиранням показати назву конкретного матеріалу й запитати підтвердження. Не дозволяти залишити пропозицію одночасно без тексту, файлів та посилань.
- У MVP прибрані/замінені матеріали виключати з актуальної пропозиції; для відновлення збоїв їх можна позначити archived. Користувацьку історію версій та її перегляд залишити для черги 2. Фізичне безповоротне видалення файлів не виконувати як частину звичайного оновлення.
- Перед збереженням показати зміни. Для успіху: «Зміни збережено. Дякуємо, що підтримуєте інформацію актуальною.»

## 5. Переривання та помилки

| Подія | Поведінка |
| --- | --- |
| «Назад» | Повернення до попереднього кроку зі збереженням чернетки |
| «Скасувати» | Відкинути поточні зміни після підтвердження; збережені пропозиції не змінювати |
| /start або головна кнопка під час анкети | «У вас є незбережені зміни. Продовжити чи скасувати?» Не створювати другу активну чернетку |
| Стара кнопка | «Ця дія вже неактуальна. Відкрийте поточне меню.» Не виконувати повторно |
| Повторне «Зберегти» | Одне подання — один результат, без дубля записів і файлів |
| Збій запису | «Не вдалося завершити збереження. Спробуйте ще раз пізніше.» Залишити чернетку для повтору, не повідомляти про успіх |
| Частковий збій файлів | Показати невдалі матеріали. Повторити або явно погодитися на подання без них до остаточного збереження |
| Чернетка втрачена або прострочена | «Незавершена анкета більше недоступна. Почніть подання ще раз.» Збережені записи не змінювати |
| Матеріал поза поданням | «Щоб додати пропозицію, натисніть “Подати пропозицію”. Щоб змінити наявну — “Оновити матеріали”.» Не створювати неповну анкету |
| Чужий запис | «Цей запис недоступний для вашого Telegram-акаунта.» Не розкривати дані компанії або власника |

## 6. Зв'язок із реєстром та вимоги реалізації

| Дані | Місце збереження |
| --- | --- |
| Компанія, контакт, необов'язкові відомості | Постачальники: company_name, contact, categories, brands, regions, terms |
| Прив'язка | Постачальники: supplier_id, telegram_user_id, telegram_chat_id, telegram_username |
| Текст | Пропозиції: offer_id, supplier_id, text |
| Файл | Матеріали: material_id, offer_id, kind=file, drive_file_id, original_name, mime_type, size_bytes |
| Посилання | Матеріали: material_id, offer_id, kind=link, source_url |
| Оновлення | Змінити лише обрані поля та updated_at; зберегти сталі ID і created_at |

Перед розробкою на етапах 3–4:

- Перевіряти Telegram-користувача на сервері перед кожною дією з компанією, пропозицією та файлом, включно зі старими кнопками. Username не використовувати як ключ доступу.
- Працювати в приватному чаті. У групі не показувати персональні дані, запропонувати приватний діалог.
- Підготувати технічні аркуші для чернеток і оброблених подій у межах Drive/Sheets. Узгодити строк очищення чернеток та їх відновлення. Чернетка не є готовою пропозицією.
- Обробляти повторну доставку події та натискання без дублів. Завершувати подання лише після запису всіх прийнятих даних; передбачити відновлення або відкат часткового збою без пошкодження попередньої пропозиції.
- Зберігати довільні назви, контакти й тексти без виконання формул у Sheets; безпечно відображати спеціальні символи в Telegram.
- Не надавати прямий доступ до приватного Drive, таблиці або даних інших компаній.
- Помилки й квоти обліковувати технічно; сповіщення власнику про кожне подання не додавати.

## 7. Друга черга

PDF-пошук та OCR; щорічне підтвердження даних повідомленням постачальнику; історія і відновлення версій; статистика ефективності. Можливий внесок 1 долар на рік розглядати лише за окремим рішенням. У поточному сценарії оплати немає.

## 8. Критерії майбутньої перевірки

Це критерії приймання, а не результати виконаних тестів бота.

| Сценарій | Очікуваний результат |
| --- | --- |
| Назва + контакт + текст | Подання без файлів дозволено |
| Назва + контакт + один прийнятий файл | Подання без тексту дозволено |
| Назва + контакт + одне посилання | Подання без файлу й тексту дозволено |
| Назва + контакт без пропозиції | Збереження не дозволено |
| Усі необов'язкові поля пропущено | Подання дозволено |
| Частина файлів не прийнята | Немає хибного повідомлення про повний успіх |
| Зміна лише контакту | Пропозиції й файли залишаються |
| Додавання файлу | Старі актуальні файли залишаються |
| Помилка під час заміни | Старий матеріал залишається актуальним |
| Прибирання єдиного матеріалу без тексту | Потрібно спочатку додати заміну або текст |
| Скасування змін | Збережений запис не змінюється |
| Повторне збереження або доставка події | Немає дубля |
| Чужий Telegram-користувач | Чужі записи недоступні |
| Подання чи оновлення | Підтвердження постачальнику; жодних сповіщень власнику |

## 9. Наступний крок

Сценарій погоджено. Перейти до етапу 3: перевірити ліміти, підготувати Apps Script та налаштування BotFather. Створення бота й публічний запуск — після окремого підтвердження. Погодження сценарію не створює та не публікує бота.
# Зміна сценарію 22.11.2026

Один Telegram-акаунт — одна компанія. Вибір компанії та створення іншої компанії вилучені. Повторне «Подати пропозицію» одразу приймає матеріали від прив'язаної компанії; «Оновити матеріали» відкриває її меню редагування. Кілька пропозицій однієї компанії дозволені; вибір пропозиції для редагування залишається. Старі кнопки іншої компанії перенаправляють до прив'язаної. Наявні множинні прив'язки потребують ручного розгляду, автоматичного об'єднання немає.


# Підтвердження завантаження 22.11.2026

Після серії файлів Worker надсилає одне спільне повідомлення з кількістю, назвами та кнопкою «Готово», дочекавшись 2 секунд без нового файла. Кожен файл записується в чернетку одразу. При швидкому натисканні «Готово» бот одразу показує підсумок і не надсилає застаріле підтвердження. Якщо надсилання продовжиться після паузи, це нова серія з окремим підтвердженням.
