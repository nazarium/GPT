## Перевірені обмеження й обраний підхід

Станом на дату перевірки:

- Стандартний Telegram Bot API дозволяє завантажувати файли до 20 МБ. У коді задано консервативний поріг 20 000 000 байтів; більші каталоги приймати посиланням. Локальний Bot API server не додаємо.
- Telegram зберігає необроблені updates не довше 24 годин. getUpdates і webhook взаємовиключні.
- Apps Script для звичайного Gmail має 20 000 URL Fetch викликів на день, 90 хвилин сумарної роботи тригерів на день та 6 хвилин на одне виконання. Відповідь URL Fetch обмежена 50 МБ. Квоти можуть змінюватися.
- Часовий тригер може спрацьовувати щохвилини. Пропонується короткий getUpdates з timeout=0, один запит за запуск, без постійного очікування. Це приблизно 1440 базових HTTP-викликів на добу плюс обробка, повідомлення та файли. Фактичний час і запас квоти виміряти під навантаженням; безперервність роботи не гарантована.
- Відповіді користувачу матимуть затримку близько хвилини, іноді довше. Прийнятність цього компромісу підтвердити перед запуском. Для миттєвого діалогу знадобиться окреме рішення для приймання webhook; його не розгортати автоматично.

Обґрунтування: в описаній Google структурі doPost(e) немає довільних HTTP-заголовків, потрібних для перевірки Telegram secret_token; ContentService також використовує перенаправлення. Це інженерна причина обрати опитування для початкової інтеграції, а не твердження, що всі webhook на Apps Script неможливі. Самого непублічного URL недостатньо для надійної перевірки джерела запиту.

Джерела:

- [Telegram Bot API](https://core.telegram.org/bots/api) — getFile, getUpdates, setWebhook, строк зберігання updates.
- [Квоти Apps Script](https://developers.google.com/apps-script/guides/services/quotas).
- [Часові тригери](https://developers.google.com/apps-script/guides/triggers/installable).
- [Web Apps: структура події](https://developers.google.com/apps-script/guides/web).
- [ContentService](https://developers.google.com/apps-script/reference/content/content-service).

## Крок 3.1. Створення бота власником

Це наступна дія користувача. Агент не створював бота і не надсилав повідомлень BotFather.

1. Відкрити офіційний [BotFather](https://t.me/BotFather) у Telegram.
2. Надіслати /newbot.
3. Назва: Archi-Create Partners.
4. Запропонований username: ArchiCreatePartnersBot. Доступність не перевірена; якщо зайнятий — ArchiCreatePartnersUaBot. Остаточний username має підтвердити BotFather.
5. Зберегти отриманий токен у власному менеджері паролів. Не надсилати його в цей чат, не додавати у Sheets, Drive-документи чи код.
6. Надіслати в чат лише підтверджений @username. Посилання на бота формувати лише після цього.

Інструкція Telegram: [From BotFather to Hello World](https://core.telegram.org/bots/tutorial#obtain-your-bot-token).

Підготовлені тексти для подальшого налаштування BotFather:

**Name:** Archi-Create Partners

**About:** Пропозиції виробників і постачальників для Archi-Create. Подання та оновлення матеріалів.

**Description:** Надсилайте пропозиції, каталоги, прайси та посилання для Archi-Create. Ми зберігаємо матеріали й звертаємося за потреби. Реєстрація не гарантує замовлень чи зустрічей.

Команда меню:

```text
start - Головне меню
```

Дві основні кнопки «Подати пропозицію» та «Оновити матеріали» створює обробник бота, а не список команд BotFather. Текст привітання брати зі сценарію етапу 2 дослівно. Групове використання не потрібне; дозволи на додавання до груп вимкнути під час налаштування.

## Крок 3.2. Створення проєкту Apps Script

Після появи бота та окремого підтвердження створення проєкту:

1. Увійти як archicreate.partners@gmail.com та відкрити [Apps Script](https://script.google.com/home).
2. Створити проєкт Archi-Create Partners. Розмістити його в папці 03_Система.
3. Додати файл Integration.gs із локальної папки apps-script цього завдання.
4. Увімкнути відображення маніфесту appsscript.json і перенести підготовлений маніфест. Часовий пояс — Europe/Kiev.
5. У Project Settings → Script properties додати TELEGRAM_BOT_TOKEN зі значенням токена, отриманого від BotFather.
6. Не додавати сторонніх редакторів: редактори Apps Script можуть отримати доступ до Script properties.
7. Запустити verifyConnection вручну, надати Google-дозволи для таблиць, Drive, зовнішніх HTTP-запитів та email поточного користувача. Перевірити, що обрано саме проєктний акаунт.
8. Очікуваний результат: правильний googleAccount, фактичний botUsername, spreadsheet=OK, folders=OK, webhook=absent. Токен у результат не виводиться.
9. За бажанням запустити testStorage: тимчасовий тестовий аркуш видаляється, тестовий файл переміщується в кошик у finally. Перевірити, що тимчасові об'єкти прибрано навіть після помилки.

Наявні інструменти інтеграції Google Drive не мають дії створення Apps Script-проєкту або керування його Script properties. Ці кроки виконати в інтерфейсі Apps Script; браузерний супровід можливий за потреби.

## Що вже робить локальний код

- verifyConnection: перевіряє акаунт, схему аркушів, власника/приватність папок, getMe і відсутність webhook. Не надсилає повідомлень і не змінює конфігурацію Telegram.
- testStorage: окрема контрольована проба запису тексту, збереження ID з початковими нулями та приватного тестового файлу з очищенням.
- partnersUpsert_: оновлює повний запис за сталим первинним ключем під блокуванням. Не створює дубль ключа; це внутрішня функція, яку слід викликати лише після авторизації й перевірок діалогу. Часткове редагування спочатку об'єднує зміни з поточним записом, зберігаючи created_at.
- partnersOwnSupplier_: перевіряє прив'язку до Telegram-користувача. ID користувача має надходити з отриманого Telegram update, а не з довільного поля анкети.
- partnersSaveFile_: перевіряє прив'язку й папку постачальника, завантажує допустимий файл Telegram і повертає приватний Drive ID. Для повтору використовує сталий material_id. Наразі ціль — приватна папка компанії; розподіл Актуальні/Архів додати в обробник життєвого циклу.
- partnersWriteLiteral_: записує введення як текст без виконання формул. Формат ID — текст.
- Обгортка Telegram приховує URL із токеном у помилках; доступні лише діагностичні getMe/getWebhookInfo та getFile. Відправлення повідомлень і запуск опитування ще не ввімкнені.
