## Обробка

Telegram → Worker → SQLite Durable Object користувача (події, чернетка, відповіді) → Apps Script → Sheets + Drive.

- /telegram перевіряє секретний заголовок, тіло до 64 КіБ, update_id і приватний чат TEST_ACTOR_ID. Чужим подіям повертається 503, а не неправдиве підтвердження.
- HTTP 2xx тільки після транзакційного запису події та alarm. PRIMARY KEY update_id забезпечує дедуплікацію, включно з одночасними повторами та завершеними подіями.
- Перший запит імпортує власні компанії, пропозиції, матеріали й чернетку з Google. Незавершені старі операції/відповіді блокують міграцію до їх узгодження.
- Dialog.gs збирається як статичний модуль без eval. Привітання, дві головні кнопки та правила анкети збережені. Звичайні кроки не звертаються до Google; «Оновити матеріали» освіжає дані з Sheets.
- План записується до зовнішніх викликів. Під час збереження надсилається «Зберігаємо матеріали», успіх — тільки після підтвердження Google. Помилка файлу повертає чернетку з кнопками повтору/виправлення.
- Стан анкети й відповідь фіксуються однією транзакцією перед sendMessage. При 429 чи недоступності Telegram відповідь залишається в черзі. Невизначений результат sendMessage може спричинити повтор тексту; «рівно один раз» не гарантується.
- Автоматичні повтори мають наростаючу паузу до 5 хвилин; Telegram retry_after має пріоритет і обмежений годиною. Незавершені події не видаляються. Завершення очищає JSON події й план, залишаючи ID для дедуплікації.
- Alarm фіксує події старше 10 хвилин; незалежний cron кожні 5 хвилин перевіряє стан. Логи містять тільки технічні лічильники/час, без контактів, текстів і токенів. Власнику сповіщення не надсилаються.

## Міст Google

Bridge.gs додається після Integration.gs, Dialog.gs, Runtime.gs. prepareBotStorage створює прихований _BridgeOperations. doPost за замовчуванням вимкнений.

Запит: version=v1, timestamp у мілісекундах, payload (рядок JSON) та signature — hex HMAC-SHA256 від `v1\n{timestamp}\n{payload}`. Допуск часу ±5 хвилин. Секрет і TEST_TELEGRAM_USER_ID перевіряються до доступу до реєстру. snapshot повертає тільки власні записи. commit перевіряє приналежність компанії, пропозиції та файлів.

Перед бізнес-записом зберігається planned з operation_id і хешем плану. Після запису й checkpoint сесії — applied. Повтор applied повертає результат без нового запису; змінений план із тим самим ID відхиляється. Частковий збій залишає planned і блокує наступний commit до повтору зі стабільними бізнес-ключами. Sheets не є транзакційною БД: часткові записи можуть бути видимі власнику до завершення повтору. Повтор snapshot лише читає власні дані, тому повтор підписаного запиту в межах строку дії безпечний.

Очікування Google lock — 15 секунд. BUSY не обробляє операцію, Worker повторює її пізніше. Старий ручний polling збережений для контрольованого відкату; його tryLock не змінено. Worker перевіряє поле ok, а не лише HTTP-статус ContentService.

## Секрети й технічні дані

Worker secrets: TELEGRAM_WEBHOOK_SECRET, INBOX_ADMIN_SECRET, GOOGLE_BRIDGE_SECRET (окремий випадковий секрет від 32 символів), TELEGRAM_BOT_TOKEN. GOOGLE_BRIDGE_URL має вигляд https://script.google.com/macros/s/DEPLOYMENT_ID/exec.

Script properties: той самий GOOGLE_BRIDGE_SECRET, BRIDGE_MODE=preview, уже наявні TELEGRAM_BOT_TOKEN та TEST_TELEGRAM_USER_ID. Секрети не передавати в чат, аргументи команд, файли репозиторію або логи. Нових OAuth scopes не додано. Автоматичні traces вимкнені, бо Telegram URL містить токен; перед увімкненням потрібне приховування таких URL.

Файли залишаються в Drive. Cloudflare зберігає технічну копію власного реєстру й чернетку — це розширює початкове рішення «тільки Sheets + Drive» і потребує підтвердження до розгортання. Чернетка старше 7 днів скидається при наступній взаємодії, але технічні дані фізично автоматично не очищуються. Ротація, резервування Worker-стану, перевірка квот та багатокористувацький режим — умови публічного запуску. Після прямого редагування Sheets натиснути «Оновити матеріали» для оновлення кешу.

/ops/status, /ops/head, /ops/session, /ops/retry потребують окремого Bearer-секрету. session експортує чернетку/кеш та кількість незавершених подій для резервування й відкату. Експорт містить персональні дані, його зберігати приватно. retry примусово обробляє голову, обходячи паузу. /ops/ack дозволений лише коли DIALOG_ENABLED=false; активний споживач сам підтверджує завершення.

## Локальна перевірка

З кореня проєкту:

```powershell
node work/archi-create-partners/worker/build.mjs
node --test --test-isolation=none work/archi-create-partners/apps-script/integration.test.mjs work/archi-create-partners/apps-script/dialog.test.mjs work/archi-create-partners/apps-script/bridge.test.mjs
node work/archi-create-partners/worker/ingress.test.mjs
node work/archi-create-partners/worker/dialog-runtime.test.mjs
```

Збірка готує work/archi-create-partners/build/webhook/Code.gs та appsscript.json. Використовуються наявні Wrangler, esbuild, Miniflare; нових пакетів немає. Google і Telegram повністю підмінені. Перевірено HMAC, строк дії, межі власника, імпорт існуючої чернетки, частковий запис, BUSY, помилку файлу, втрату Google ACK, конкурентні дублікати, порядок, прострочену подію, 429 і повний перезапуск з незавершеною анкетою/відповіддю. Згенерований сценарій звіряється з оригіналом у runtime-тестах.

## Приватне розгортання — після окремого підтвердження

1. Перевірити акаунт Cloudflare, безкоштовний тариф, доступність SQLite Durable Objects і квоти. Платні послуги не активувати. Підтвердити зберігання технічних даних у Cloudflare.
2. Зберегти резервну копію Google-коду/реєстру, зупинити polling, узгодити planned/непідтверджені відповіді й останній update_id. getUpdates і webhook одночасно не запускати.
3. Завантажити зібраний Code.gs у наявний Apps Script, виконати prepareBotStorage, налаштувати секрети та BRIDGE_MODE. Розгорнути web app від імені власника з доступом для зовнішніх запитів; самі Sheets/Drive залишити приватними. Міст захищений HMAC.
4. Розгорнути окремий archi-create-partners-preview. Для workers.dev URL окремо змінити workers_dev=false на true; налаштувати секрети, GOOGLE_BRIDGE_URL, MODE=preview і DIALOG_ENABLED=true. Сайт archi-create не перерозгортати. HTTPS URL буде доступним з інтернету, але дані й дії захищені секретами.
5. Перевірити міст, імпорт власної компанії та діагностику. setWebhook: max_connections=1, allowed_updates=[message,callback_query], secret_token, drop_pending_updates=false. Кнопку на сайт поки не додавати.
6. Перевірити у своєму чаті подання, контакт, посилання, PDF, оновлення, повтор після збою; звірити Sheets/Drive, дублікати та приватність. Виміряти затримку. Ціль до 5 секунд для кроків анкети ще не виміряна; початковий імпорт і запис Google можуть тривати довше.

Відкат: припинити нову доставку без drop_pending_updates, зберегти й узгодити прийняту Worker-чергу, експортувати /ops/session і перенести останній стан у _Sessions Google, лише потім відновлювати polling. Саме deleteWebhook не поверне в Telegram уже підтверджені Worker події. Експорт перевірено локально; перенесення стану назад у живий Google треба перевірити до реального перемикання.

Джерела: [Telegram webhook](https://core.telegram.org/bots/api#setwebhook), [SQLite storage](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/), [alarms](https://developers.cloudflare.com/durable-objects/api/alarms/), [Apps Script web apps](https://developers.google.com/apps-script/guides/web).
