Стан на 14.11.2026: інтеграція підготовлена для наявного Worker `archi-create`. Публікації за замовчуванням вимкнені. Власний Meta API, WordPress, AI-контент і платні посередники не використовуються.

## Підтверджена структура

- Локальний сайт: `C:/Users/nazar/OneDrive/Документи/ChatGPT/Arch-Create.com.ua`.
- React 19.2.0, esbuild 0.25.12, JavaScript ESM, pnpm. Додано локальний Wrangler 4.161.0; версії React/esbuild збережено.
- Наявний `cloudflare/worker.mjs` обслуговує сайт, `PortfolioStore` у Durable Object зберігає правки адміністратора, стан приховування та завантажені фото. Це сховище залишається на місці.

На диску відсутня частина актуальних правок Durable Object — не можна будувати чергу лише зі статичного JSON.
- Cron отримує каталог безпосередньо через наявний binding `PORTFOLIO`, тим самим шляхом `/api/projects`. Новий зовнішній скрапер не потрібен. Основний ключ — стабільний `id`, а не назва або позиція картки.
- Фото: `assets/projects/<id>/*.{jpg,png,webp}` і `assets/projects/cloud/<uuid>.*`. URL залишаються на сайті. Посилання на проєкт — `/projects/<slug>/`.

## Правила черги

1. Перший імпорт позначає видимі проєкти як `archive`, подальші нові ID — `new`. Усі починають без готовності.
2. Готовність до соцмереж задається окремо через захищений адміністративний запит `ready` із SHA-256 поточного вмісту. Вона не дорівнює публікації на сайті. Після зміни назви/опису/порядку або URL фото готовність скидається. Зміни двійкового вмісту за незмінним URL цим хешем не відстежуються; завантаження сайту використовують унікальні URL.
3. Вівторок і п’ятниця, 10:00 за `Europe/Kyiv`: один готовий архівний проєкт на слот. Cron запускається кожні 15 хвилин у UTC; локальний час обчислюється з урахуванням літнього часу. Пропущений слот не наздоганяється масовою публікацією.
4. Готовий `new` потрапляє в чергу на наступному запуску. Один Worker-запуск надсилає одну платформу; три платформи можуть обробитися за три години. Buffer отримує час на 15 хвилин уперед. Нові проєкти мають пріоритет перед архівом.
5. Текст = назва + номер на сайті, наявний опис (якщо є), посилання. Опис не вигадується, текст і фото не обрізаються автоматично.
6. PRIMARY KEY `(project_id, platform)` зберігає історію після змін чи повторного появлення проєкту. ID каналу фіксується. Зміна мапінгу не переносить дописи на інший акаунт непомітно.
7. Перед надсиланням перевіряються доступність, заголовки, розміри й пропорції фото, актуальність каталогу та стан каналу. Читаються лише перші 64 KiB кожного фото; потрібні повний розмір у HTTP-заголовку й JPEG/PNG/WebP заголовки.
8. У D1 до виклику Buffer фіксується `sending` з унікальним токеном спроби. Після таймауту, 5xx, неповної відповіді або перерваного запису — `uncertain`, без автоматичного повторного створення. У `createPost` немає документованого idempotency key; абсолютну exactly-once гарантію між D1 і Buffer дати неможливо.
9. 429 повторюється з відкладенням, максимум 5 спроб. Відхилена валідація/авторизація — `blocked`. Відомий пост Buffer з помилкою — `failed`: повторно створювати його автоматично не можна, виправлення виконується у Buffer, статус оновлюється через `refresh`.
10. `scheduled` означає лише прийнятий Buffer допис. `sent` для автоматичного посту підтверджується API, зберігаються Buffer ID і посилання. Для `notification` навіть статус Buffer `sent` не є доказом публікації: залишається `manual_required`, доки людина не надасть URL готового допису.

Надмірні галереї: проєкт `258288907` має 18 фото, `252328583` — 12. Для Facebook/TikTok зберегти їх усі в одному дописі через Buffer не можна. Типово така платформа блокується. Потрібен явний вибір до 10 оригінальних фото або ручна публікація поза Buffer у межах можливостей самої платформи. Додавати нові дописи для залишку автоматично заборонено.

## Налаштування і деплой

У Cloudflare створено D1 `archi-create-social` (`eeb932fd-33cc-493f-a955-74ba3984b7ae`, EEUR) та застосовано міграцію. Це не сховище фотографій. Наявні Worker, Durable Object і маршрути збережені.

Для іншого акаунта створіть власну D1 та замініть ідентифікатор:

```powershell
pnpm install --frozen-lockfile
pnpm exec wrangler whoami
pnpm exec wrangler d1 create archi-create-social
pnpm exec wrangler d1 migrations apply SOCIAL_DB --local
pnpm exec wrangler d1 migrations apply SOCIAL_DB --remote
node scripts/build.mjs
node scripts/build-admin.mjs
pnpm run test:social
pnpm exec wrangler deploy --dry-run
```

Перевірте акаунт, поточну хмарну версію, актуальність локальних файлів і налаштування перед деплоєм. Оригінальний `ADMIN_PASSWORD` залишається секретом Cloudflare. Не виводьте секрети й не передавайте їх у чат.

Спочатку розгортайте з `SOCIAL_MODE="dry-run"`, `BUFFER_CHANNELS="[]"`; у D1 `live=0`, жоден проєкт не готовий. У цьому режимі Cron синхронізує каталог, але не звертається до Buffer.

```powershell
pnpm exec wrangler deploy
pwsh social/scripts/admin.ps1 -Action sync
pwsh social/scripts/admin.ps1 -Action status
```

Для локального запуску потрібна окрема локальна D1, не `--remote`:

```powershell
pnpm exec wrangler dev --local --test-scheduled --infer-origin-from-routes false
```

При створенні нової інсталяції перший імпорт архіву слід виконати до додавання нових проєктів. Масове приховування всіх проєктів дасть порожній видимий каталог; наявна історія D1 не видаляється.

## Безпечне підключення Buffer

1. У Buffer Free підключіть саме потрібні Instagram Business/Creator, Facebook Page і TikTok. Перевірте акаунти, права, часовий пояс і режим сповіщень. Для ручного завершення потрібен мобільний Buffer із дозволеними push-повідомленнями. Фотопости TikTok на мобільному можуть бути обмежені; запасний варіант — локальний пакет із JSON-перегляду та оригінальні фото.
2. Створіть ключ у [налаштуваннях Buffer](https://publish.buffer.com/settings/api). Збережіть через Cloudflare Dashboard → Worker → Settings → Variables and Secrets → Secret `BUFFER_API_KEY`, або інтерактивно:

```powershell
pnpm exec wrangler secret put BUFFER_API_KEY
```

Команда створює та розгортає версію Worker; робіть це, залишаючи режим `dry-run`. Не записуйте ключ у `wrangler.jsonc`, аргументи команди, файли звіту або повідомлення. Введення відбувається лише у захищеному запиті інструмента/термінала. `ADMIN_PASSWORD` не є ключем Buffer.

3. Через захищений запит дізнайтеся організацію. Скрипт запитує пароль адміністратора сайту локально:

```powershell
pwsh social/scripts/admin.ps1 -Action organizations
```

Запишіть ID у `BUFFER_ORGANIZATION_ID`, розгорніть із `dry-run`, потім прочитайте канали:

```powershell
pwsh social/scripts/admin.ps1 -Action channels
```

4. `BUFFER_CHANNELS` — JSON-рядок до трьох каналів. Підставте реальні ID, не назви профілів:

```json
[
  {"platform":"instagram","id":"INSTAGRAM_CHANNEL_ID","mode":"automatic"},
  {"platform":"facebook","id":"FACEBOOK_PAGE_CHANNEL_ID","mode":"automatic"},
  {"platform":"tiktok","id":"TIKTOK_CHANNEL_ID","mode":"notification"}
]
```

Повторно розгорніть із `SOCIAL_MODE="dry-run"`. Секрети зберігаються окремо. Зміна підключених акаунтів після активації потребує повторного погодження мапінгу; вже створені рядки на старий канал автоматично не переносяться.

## Перша публікація — лише після погодження

Без погодження реальних публікацій дозволені preview/dry-run, читання Buffer та окремо погоджене створення чернеток. Користувач погодив 5 проєктів на 3 платформах: 15 чернеток збережено в обліку D1. Це не означає дозвіл на публікацію.

Перевірте один проєкт та збережіть отриманий `fingerprint`:

```powershell
pwsh social/scripts/admin.ps1 -Action preview -ProjectId 179472281
```

Погодження має охоплювати конкретний проєкт, фото/можливе обрізання Instagram, текст, акаунти, час і ручний режим TikTok. Після погодження позначте лише тестовий проєкт готовим:

```powershell
pwsh social/scripts/admin.ps1 -Action ready -ProjectId 179472281 -Fingerprint HASH_FROM_PREVIEW
```

Для погодженого відбору фото використовуйте нульові індекси з `project.images`; без цього поле всі фото зберігає. Наприклад:

```powershell
pwsh social/scripts/admin.ps1 -Action ready -ProjectId PROJECT_ID -Fingerprint HASH_FROM_PREVIEW -SelectionJson '{"facebook":[0,1,2],"tiktok":[0,1,2]}'
```

Перевірте, що інших готових проєктів немає. Лише після явного дозволу на реальні публікації змініть `SOCIAL_MODE` на `live`, розгорніть, виконайте:

```powershell
pwsh social/scripts/admin.ps1 -Action activate
```

Скрипт попросить підтвердження `APPROVE_FIRST_PUBLICATION`. Це вмикає реальне планування всіх позначених готовими проєктів, а не лише показаний preview. Для архіву дочекайтеся вівторка/п’ятниці о 10:00; нові готові проєкти перевіряються кожні 15 хвилин. Надсилання платформ поступове — максимум одна за запуск.

Перевірте Buffer ID, кінцеві статуси й фактичні дописи. Перед переведенням TikTok у `automatic` потрібен окремо погоджений тест саме фотогалереї через API й перевірка її фактичного URL. До такого тесту не стверджуйте, що режим працює для цього акаунта; залишайте `notification`/ручний пакет.

## Керування і відновлення

Усі маршрути `/api/admin/social/*` захищає наявний пароль адміністратора; для POST потрібен точний Origin сайту. Публічного методу запуску постингу немає. Публічний вигляд сайту збережено. До наявної адмінпанелі додано вкладку «Соцмережі»; PowerShell-скрипт та захищені API-запити також доступні.

| Дія | Призначення |
|---|---|
| `status` | Режим, проєкти, готовність, стани платформ і останні події |
| `sync` | Імпорт видимого каталогу без Buffer |
| `preview` | Назва, опис, фото, хеш та майбутні запити Buffer, без запису у Buffer |
| `ready` / `unready` | Готовність конкретної версії проєкту; вже заплановані у Buffer дописи не скасовуються |
| `pause` | Вимкнення нових надсилань із Worker. Уже заплановані дописи залишаються у Buffer: окремо призупиніть черги/видаліть потрібні дописи там |
| `adopt` | При `uncertain` приєднати наявний `BufferId`; звіряються канал, текст і фото |
| `retry-confirmed-absent` | Лише після ручної перевірки відсутності попереднього допису в усіх розділах Buffer; потрібна явна фраза підтвердження |
| `refresh` | Перечитати статус відомого Buffer ID після виправлення збою в самому Buffer |
| `complete-manual` | Після ручної публікації додати фактичний `ExternalUrl`; це не викликає публікацію |

```powershell
pwsh social/scripts/admin.ps1 -Action pause
pwsh social/scripts/admin.ps1 -Action adopt -ProjectId PROJECT_ID -Platform instagram -BufferId BUFFER_POST_ID
pwsh social/scripts/admin.ps1 -Action refresh -ProjectId PROJECT_ID -Platform instagram
pwsh social/scripts/admin.ps1 -Action complete-manual -ProjectId PROJECT_ID -Platform tiktok -ExternalUrl https://www.tiktok.com/@ACCOUNT/photo/POST_ID
```

Втрата D1 або створення нової бази не повинні запускати повторний імпорт як нові публікації. Перед відновленням збережіть/відновіть таблицю `social_publications`, звірте Buffer-історію; використовуйте D1 export/Time Travel відповідно до тарифу. Відкат коду не відкочує D1 або Durable Object.

## Перевірки

- 36 тестів, зокрема на реальному SQLite з адаптером D1 та workerd: транзакції, ідентичність проєктів, окремі платформи, конкурентне захоплення, архівні слоти, нові проєкти, готовність, DST, ліміти фото, 429, невизначені результати, збій запису після успіху Buffer, захист від повторів і активація.
- Міграція перевірена на локальному workerd/D1 та застосована до нової хмарної D1.
- Локальний Worker: головна 200, каталог 56 початкових записів, admin без входу 401, неправильний Origin 403, sync 200, Cron 200; режим dry-run, 0 готових і 0 публікацій.
- Повна збірка сайту та `wrangler deploy --dry-run` пройшли. JavaScript публічного сайту лишився тим самим; адміністративний bundle оновлено.
- Перевірено доступність і заголовки всіх 241 фото публічного каталогу: помилок доступу 0. Instagram 48/51 проходять статичні умови, Facebook 49/51, TikTok 49/51 у режимі повідомлень. Це не гарантує прийняття Buffer або кінцеву публікацію.
- Підключення Buffer перевірено через захищений Worker; звірено 15 погоджених чернеток із фото та датами. Ключ зберігається як Cloudflare secret. Фактичні публікації та TikTok automatic не тестувалися.

## Адмінвкладка «Соцмережі»

Вхід: https://archi-create.com.ua/admin?section=social — наявний пароль адміністратора.

- Черга: пошук, фільтри, готовність, вибір і порядок наявних фотографій окремо для платформ, попередній перегляд тексту та створення чернеток із захистом від повторів.
